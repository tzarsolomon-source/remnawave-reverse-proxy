# Bunny DNS и сертификаты Remnawave Node

В меню выпуска сертификатов добавлен пункт **5. Bunny.net DNS API**.
Cloudflare, Gcore, HTTP-01 и загрузка своих сертификатов сохранены.

## Выпуск сертификата

1. DNS-зона домена должна обслуживаться Bunny DNS. Записи A/AAAA для доступа
   к серверу задаются отдельно; создание таких записей через Bunny не добавлено.
2. При установке или через «Управление SSL → Генерация» выберите Bunny.
3. Выберите отдельный домен или wildcard. Например, для `node.example.com`:
   - отдельный сертификат содержит только `node.example.com`;
   - wildcard с базовым доменом `example.com` содержит `example.com` и `*.example.com`.
4. Введите API-ключ аккаунта Bunny.net. Ввод скрыт. Ключ сохраняется в
   `~/.secrets/certbot/bunny.ini` с правами `600` для автоматического продления.

Для wildcard скрипт запрашивает базовый домен явно. Это позволяет использовать
`example.co.uk` и подзоны вроде `vpn.example.com`, не ограничиваясь последними
двумя частями имени. Wildcard покрывает один уровень поддоменов.

Плагин [certbot-dns-bunny](https://github.com/mwt/certbot-dns-bunny)
устанавливается при первом использовании. Проверка DNS-01 выполняется через
временные TXT-записи; ожидание распространения — 120 секунд. Email для
Let's Encrypt можно оставить пустым.

## Сертификат внутри ноды

При установке отдельной ноды и «панель + нода», для Nginx и Caddy, сервис
`remnanode` получает сертификат домена ноды (`SELFSTEAL_DOMAIN`):

```yaml
    volumes:
      - /dev/shm:/dev/shm:rw
      - /var/log/remnanode:/var/log/remnanode
      - /etc/letsencrypt/live/DOMAIN/fullchain.pem:/ssl/fullchain.pem:ro
      - /etc/letsencrypt/live/DOMAIN/privkey.pem:/ssl/privkey.pem:ro
```

`DOMAIN` заменяется фактическим именем каталога сертификата: например,
`node.example.com`, `example.com` для wildcard или `example.com-0001`.
Проверяются наличие обоих файлов и соответствие сертификата домену.
В конфигурации TLS ноды используйте `/ssl/fullchain.pem` и `/ssl/privkey.pem`.

В варианте Caddy сертификат домена ноды также используется для selfsteal-сайта.
Сертификатами панели и страницы подписки Caddy продолжает управлять сам.
Certbot deploy-hook перезапускает работающие контейнеры ноды и веб-сервера
после успешного продления, чтобы обновились монтирования отдельных файлов.
Для HTTP-01 хуки временно освобождают порт 80 и восстанавливают контейнеры,
которые работали до продления.

Изменение шаблонов применяется при установке. Уже развёрнутый Compose не
переписывается через меню генерации сертификатов: для существующей ноды
добавьте эти два монтирования и выполните `docker compose up -d remnanode`.

## Запуск версии из архива и применение патча

Архив содержит полный исходный код. Распакуйте его и запускайте на целевом
сервере из каталога с `install_remnawave.sh`:

```bash
sudo bash ./install_remnawave.sh
```

До публикации изменений в GitHub запускайте именно эту локальную копию:
модули берутся из соседнего каталога `src/`. Команда установки из README
загружает версию, опубликованную в ветке `main` форка.

Патч подготовлен относительно коммита `7793be2`:

```bash
git apply --check /path/to/remnawave-bunny.patch
git apply /path/to/remnawave-bunny.patch
```

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

Требуются Bash, OpenSSL, Python 3 и PyYAML. Тесты используют локальные
сертификаты и подмену внешних команд; DNS и Let's Encrypt не вызываются.
Проверены оба режима Bunny, сохранение Cloudflare/Gcore, пути wildcard и
Certbot `-0001`, ошибки выпуска, меню, четыре шаблона Compose и хуки продления.
Реальный выпуск и запуск Docker необходимо проверить на целевом сервере.
